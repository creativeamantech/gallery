PHASE 8 IMPLEMENTATION PLAN

1. WebView Lifecycle & Ownership Model
- Create `ActiveWebViewRegistry` (Singleton).
- Use `WeakReference<WebView>` to track the currently active WebView safely without leaking memory or retaining destroyed Activities.
- Add `attach(WebView)` and `detach(WebView)` methods.

2. Navigation Architecture & JS Bridge
- `AndroidWebViewObservationProvider` and `AndroidWebViewInteractionProvider` will resolve the WebView via `ActiveWebViewRegistry.get()`.
- If null, return `CapabilityAvailability.UNAVAILABLE`.
- No new Java-to-JS `@JavascriptInterface` objects are needed. Instead, we use `WebView.evaluateJavascript` to inject structured JS payloads and retrieve results. This inherently runs in the WebView's JS context safely.

3. Existing WebView Clients
- `GalleryWebView` currently accepts an `onWebViewCreated` callback. 
- We will minimally update `GalleryWebView` (or its consumers) to attach to `ActiveWebViewRegistry` in `onWebViewCreated` and detach in `onRelease`.
- `BaseGalleryWebViewClient` and other client logic remain completely unchanged, preserving existing URL intercept and console behaviors.

4. Hilt Integration & Provider Attachment
- Create `app/src/main/java/com/google/ai/edge/gallery/capabilities/web/android/AndroidWebViewObservationProvider.kt`
- Create `app/src/main/java/com/google/ai/edge/gallery/capabilities/web/android/AndroidWebViewInteractionProvider.kt`
- Update `WebCapabilityModule` to provide these Android implementations (bound to the universal interfaces) instead of the `Fake` providers.

5. Exact Files to Create
- `app/src/main/java/com/google/ai/edge/gallery/capabilities/web/android/ActiveWebViewRegistry.kt`
- `app/src/main/java/com/google/ai/edge/gallery/capabilities/web/android/AndroidWebViewObservationProvider.kt`
- `app/src/main/java/com/google/ai/edge/gallery/capabilities/web/android/AndroidWebViewInteractionProvider.kt`
- `app/src/main/java/com/google/ai/edge/gallery/capabilities/web/android/WebJavascriptTemplates.kt` (Holds safe JS extraction logic)
- `app/src/androidTest/java/com/google/ai/edge/gallery/capabilities/web/android/UniversalAgentWebViewTestActivity.kt`
- `app/src/androidTest/java/com/google/ai/edge/gallery/capabilities/web/android/AndroidWebViewProvidersTest.kt`

6. Exact Files to Modify
- `app/src/main/java/com/google/ai/edge/gallery/capabilities/web/WebCapabilityModule.kt`: Update to inject Android providers.
- `app/src/main/java/com/google/ai/edge/gallery/ui/common/GalleryWebView.kt`: Inject/attach to registry upon creation and detach on release.
- `app/src/main/AndroidManifest.xml`: Register the `UniversalAgentWebViewTestActivity` for instrumentation tests.
- `app/src/test/java/com/google/ai/edge/gallery/capabilities/web/WebCapabilitiesTest.kt`: Ensure pure JVM tests continue to use `FakeWebProviders`.

7. Instrumentation Strategy
- `UniversalAgentWebViewTestActivity` will host a `GalleryWebView` loaded with a local deterministic HTML string (`loadDataWithBaseURL`).
- `AndroidWebViewProvidersTest` will use standard Compose test rules to launch the activity, wait for `pageFinished`, and directly call `AndroidWebViewObservationProvider` and `AndroidWebViewInteractionProvider` to verify real JS DOM extraction and interaction.

8. Security Considerations
- Navigation targets are validated: schemas restricted to `http`, `https` (plus `data` for our local test). `javascript:` will be explicitly rejected by the interaction provider returning `NAVIGATION_BLOCKED`.
- JS payloads are hardcoded templates (in `WebJavascriptTemplates`), completely isolated from LLM-generated code.
- Passwords and sensitive input values are redacted to `***` within the JS template *before* reaching Kotlin, and strictly enforced again in Kotlin. No arbitrary script evaluation is exposed to the Agent.

9. Performance Considerations
- The DOM JS extractor enforces strict bounds: Max depth = 15, Max nodes = 500, Max string length = 200.
- `evaluateJavascript` is executed safely on the Main thread using Kotlin coroutines (`suspendCancellableCoroutine`) with timeout boundaries to prevent blocking the coroutine context indefinitely.
- Irrelevant nodes (scripts, styles, layout wrappers without text/interactivity) are pruned during JSON serialization.
